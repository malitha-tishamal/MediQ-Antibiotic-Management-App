The problem

Paper registers cannot answer the questions stewardship teams ask.

Manual antibiotic tracking across a main store, clinical wards and a return store creates discrepancies that are hard to trace. Quantities drift between the register and the shelf, near-expiry stock is discovered late, and ward-level consumption is difficult to reconstruct when it is needed for review.

MediQ records every movement as a linked transaction — who released what, to which ward, from which book and page — while keeping the physical paperwork your staff already uses.

  • Each release and return is an auditable record, not a running total.
  • Stock deductions happen inside a single atomic Firestore transaction.
  • Book and page numbers keep digital records matched to Ward Drug Order Books.

Capabilities

Built around the movements a pharmacy actually records.

Every feature maps to a real task in the antibiotic lifecycle — no dashboards that only look good in a demo.

Transaction-safe releases

Dispensing to a ward deducts from main_stock inside an atomic Firestore transaction, so concurrent updates cannot double-count stock.

Structured return handling

Accept unused or expired medicines from a ward and let MediQ restock the returned quantities into return_stock as part of the same record.

Live Main & Return Store visibility

Monitor both stores from one screen, with low-stock alerts that surface what needs attention before the next ward order is placed.

TypeAhead catalogue and ward search

Find an antibiotic or a hospital ward in a few keystrokes. Predictive search replaces scrolling through long registers during busy dispensing rounds.

Book and page order tracking

Capture the Book Number and Page Number of the physical Ward Drug Order Book against each release, keeping digital and paper records reconcilable.

Audit-ready PDF and CSV exports

Generate formatted PDF certificates and CSV spreadsheets for inventories and transaction logs, ready for internal audit or stewardship review.

Adoption path

From a pending account to a stewardship report.

MediQ is deployed into an existing pharmacy workflow rather than replacing it.

  1. 01

    Request an account

    A pharmacist self-registers with email and NIC verification details. New accounts are created with a Pending status.

  2. 02

    Administrator approval

    An authorised administrator reviews the request in the user governance screen. No application features are reachable until approval.

  3. 03

    Release and return

    Dispense to a ward with book and page references, then record returns as unused stock comes back from the ward.

  4. 04

    Analyse and export

    Review trends, category distribution and ward-wise consumption, then export PDF or CSV records for audit and review.

Account status and role checks are enforced through Firebase Auth and Firestore, not just hidden buttons in the interface.

Questions

Before you evaluate MediQ.

Straight answers about access, deployment and what the system does — and does not — do.

Still have a question?
Who can create a MediQ account?

Registration is intended for hospital pharmacy staff. A self-registered account is created with a Pending status by default and cannot access application features until an administrator approves it.

Does MediQ replace BHTs or Ward Drug Order Books?

No. MediQ is designed to run alongside existing paper records. It captures the Book Number and Page Number of the physical ward order book against each release, so the digital record can be reconciled with the paperwork.

What happens to stock during a release or return?

Releases deduct quantities from main_stock and returns restock return_stock. Both operations are written as atomic Firestore transactions, which prevents partially applied stock changes if a write fails.

Which platforms are supported?

MediQ is built with Flutter from a single codebase, targeting Android, iOS, web and desktop. The repository documents all of these targets; the appropriate build for a facility depends on its devices and network.

Can we export records for audit?

Yes. Inventory records and transaction logs can be exported as formatted PDF certificates and CSV spreadsheets, which can be printed, shared or archived with other hospital documentation.

How is access to data controlled?

Authentication and account lifecycle are handled by Firebase Auth, with role and status information stored in Firestore. Credentials for external services are loaded at runtime from environment configuration and are intentionally excluded from the repository.

Is MediQ a clinical decision-support tool?

No. MediQ manages inventory movements and usage analytics. It does not recommend therapy, interpret microbiology results, or replace pharmacist and clinician judgement.

Is the source code open source?

MediQ is proprietary software developed for healthcare facility antibiotic management, and all rights are reserved. The public repository is available for reference and review; it is not offered under an open-source licence.
